# Lynn PASS 

> **구두보고의 대기와 시간을 관리하는 AI Queue System**
> 보고자는 기다리지 않고, 결재자는 원하는 때에.

전자결재는 디지털화됐지만, 결재자를 직접 찾아가 하는 **구두보고**는 아직 아날로그입니다.
Lynn PASS는 구두보고에 순번과 예상 대기시간을 붙여, 보고자는 자리에서 기다리지 않고 호출을 받고, 결재자는 자신의 일정에 맞춰 보고를 받을 수 있게 합니다.

## 주요 기능

**보고자**
- 결재자 선택(이름·팀·본부 검색, 즐겨찾기)과 결재자의 주간 보고 가능 일정 확인
- 보고 내용·예상 소요시간(5/10/15/20분)·긴급 여부를 입력해 대기열에 등록
- 내 순번과 예상 대기시간 실시간 확인, 호출 알림("지금 입장하세요")과 응답
- 다음 사람과 순서 교환, 대기열 나가기

**결재자**
- 보고 가능 / 일시중단 / 보고불가 상태 설정, 요일·오전/오후 단위 주간 일정 설정
- 대기 목록 확인, 다음 보고자 호출, 우선 호출, 보고 완료 처리
- 호출 후 5분 안에 응답이 없으면 순서가 뒤로 밀리는 규칙

**공통**
- 실제 보고 소요시간 기록을 바탕으로 한 예상 대기시간 보정
- Supabase Realtime으로 여러 기기·계정 화면이 즉시 동기화

## 기술 구성

- 단일 파일 `index.html` (React 18 UMD, 빌드 과정 없음)
- 백엔드: [Supabase](https://supabase.com) (`people`, `queue`, `history` 테이블, Realtime)
- 호스팅: GitHub Pages

## 직접 실행해 보기

1. 이 저장소를 내려받거나 포크합니다.
2. Supabase 프로젝트를 만들고 `people`, `queue`, `history` 테이블과 Realtime을 설정합니다.
3. `index.html` 상단의 `window.SUPABASE_URL` / `window.SUPABASE_ANON_KEY`를 본인 프로젝트 값으로 바꿉니다.
4. GitHub Pages(Settings → Pages → Branch: `main`)로 배포하거나 `index.html`을 브라우저로 엽니다.
5. 처음 접속하면 테이블이 비어 있을 때 샘플 조직도가 자동으로 채워집니다. 앱 안의 "데모 데이터 초기화"로 언제든 되돌릴 수 있습니다.
